# سجل الفصل

برنامج ويب بواجهة عربية من اليمين لليسار لتسجيل الطلاب والدرجات والحضور وتصدير تقارير Excel. الخادم مكتوب بلغة Python، والواجهة تعمل في المتصفح، ويمكن تثبيت الموقع كتطبيق على الهاتف واللوحي والكمبيوتر. تُحفظ البيانات على Neon مع نسخة محلية في المتصفح للعمل عند انقطاع الاتصال.

## هيكل المشروع

```
.
├── render.yaml        إعداد نشر الخادم على Render
├── app.py             خادم Python وواجهة API وقاعدة البيانات
├── requirements.txt   اعتماديات Python
├── public/            ملفات الموقع
│   ├── index.html
│   ├── style.css
│   ├── app.js
│   ├── sw.js          العمل دون اتصال
│   ├── manifest.webmanifest
│   └── icon*.png / icon.svg
└── README.md
```

## إدخال الدرجات

- من ملف الطالب اختر **تاريخ الإدخال** ثم اضغط خانة الدرجة وبعدها الرقم، فتُسجَّل بهذا التاريخ.
- يمكنك تسجيل **أكثر من درجة في اليوم الواحد** (واجبان واختبار مثلاً)، وفي أيام مختلفة. بعد آخر درجة تظهر دائماً خانة **+ جديدة**، فلا يوجد حد لعدد الدرجات.
- الإدخال اليدوي يتيح كتابة الدرجة والدرجة النهائية والتاريخ وملاحظة.
- في **سجل الطالب** يظهر لكل درجة تاريخها وشهرها، ويمكن تعديل التاريخ مباشرة.

## التصدير

يُنتج البرنامج ملف `.xlsx` حقيقياً بدون أي مكتبة خارجية، بصفحة من اليمين لليسار:

- **النطاق:** كل طلاب الفصل، أو طالب واحد، أو طلاب معينون.
- **الدرجات والمتوسطات معاً (الأفضل):** ملف واحد بأربع أوراق:
  - **المتوسطات:** متوسط ونسبة وعدد درجات كل نوع (الواجب، الاختبار…) لكل طالب، ثم المجموعات والإجمالي.
  - **كل الدرجات:** كل درجة في عمود، مرتبة من الأقدم إلى الأحدث.
  - **السجل التفصيلي:** صف لكل درجة بتاريخها وشهرها ونوعها ومجموعتها، مع أسهم تصفية في العناوين.
  - **المتوسط الشهري:** متوسطات كل شهر على حدة.
- **كل الدرجات المدخلة فقط**، أو **المتوسطات فقط**.
- لكل نوع من الدرجات لون خاص، والأنواع داخل مجموعة (مثل المشاركة اليومية) تأخذ لون المجموعة.
- خيار إضافة أعمدة الحضور والغياب.

## المشاركة اليومية (12 درجة)

من **الإعدادات** اضغط **إضافة قالب المشاركة اليومية (12 درجة)** فيُضاف:

| المكوّن | الدرجة | طريقة الإدخال |
|---|---|---|
| اختبار الخميس | 6 | اختبارات من 10، وتُحوَّل بمعادلة (مجموع الطالب ÷ الممكن) × 6 |
| التفاعل داخل الصف | 4 | رموز + ✓ − من خريطة الجلوس (وضع «تسجيل التفاعل»)، وتُقرَّب إلى نصف درجة |
| الانضباط والاستعداد | 2 | درجتان (أدوات، هدوء) ويمكن إنقاص نصف درجة |

- في خريطة الجلوس اختر **تسجيل التفاعل** واضغط المقعد لتبديل الرمز (+ ← ✓ ← − ← مسح) لتاريخ الحصة المحدد.
- الرموز تُحسب هكذا: + = 1، ✓ = 0.75، − = 0، ثم متوسط الحصص × 4.
- غياب الطالب بعذر لا يُحسب صفراً، لأن المتوسط يؤخذ من الدرجات المدخلة فقط.
- المجموع من 12 يظهر في ملف الطالب وفي جدول الدرجات وفي ملف Excel.
- يمكنك تعديل الأوزان والأسماء أو إنشاء مجموعات أخرى من أنواع الدرجات في الإعدادات (الدرجة المعتمدة + المجموعة).

## تشغيله على جهازك

يلزم Python 3.10 أو أحدث وقاعدة PostgreSQL متاحة (مثل Neon). اضبط متغيري البيئة `DATABASE_URL` و`APP_PASSWORD` قبل التشغيل. يجب أن تكون كلمة المرور 12 حرفاً على الأقل.

```bash
python -m venv .venv
python -m pip install -r requirements.txt
python -m flask --app app run --port 3000
```

في Windows PowerShell اضبط المتغيرين للجلسة الحالية قبل التشغيل:

```powershell
$env:DATABASE_URL = "رابط الاتصال من Neon"
$env:APP_PASSWORD = "كلمة مرور قوية لا تقل عن 12 حرفاً"
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m flask --app app run --port 3000
```

ثم افتح `http://localhost:3000`. عند ظهور نافذة تسجيل الدخول في المتصفح، أدخل اسم المستخدم `teacher` وكلمة المرور المحددة في `APP_PASSWORD`.

## النشر على Neon وRender

Neon يوفر قاعدة PostgreSQL، بينما يشغّل Render موقع Python وواجهة API:

1. أنشئ قاعدة بيانات في Neon وانسخ رابط الاتصال `DATABASE_URL` من لوحة Neon. استخدم رابط الاتصال المشفر (TLS).
2. ارفع المشروع إلى مستودع GitHub.
3. في Render اختر **New** ثم **Blueprint**، واربط المستودع ليقرأ إعدادات `render.yaml`.
4. من إعدادات الخدمة في Render، أضف `DATABASE_URL` والصق رابط Neon، ثم أضف `APP_PASSWORD` واختر كلمة مرور قوية من 12 حرفاً أو أكثر.
5. أعد نشر الخدمة وافتح رابط Render. اسم المستخدم في نافذة الدخول هو `teacher`، وكلمة المرور هي قيمة `APP_PASSWORD`.

ينشئ خادم Python جدول التخزين تلقائياً عند أول تشغيل. لا تضع رابط Neon أو كلمة المرور في ملفات المشروع أو في JavaScript الذي يعمل في المتصفح؛ تُضبط هذه القيم كمتغيرات بيئة في Render.

## أين تُحفظ البيانات؟

تُحفظ البيانات في قاعدة Neon، مع نسخة محلية احتياطية في متصفح الجهاز (`localStorage`). عند توفر الاتصال، يزامن البرنامج التغييرات مع Neon. عند تعذر الاتصال، يستمر الحفظ محلياً ويظهر تنبيه بجانب عنوان البرنامج؛ أعد فتح البرنامج عند عودة الاتصال لمتابعة المزامنة. هذا يعني:

- عند الاتصال بالخادم، تظهر البيانات نفسها على الأجهزة التي تسجل الدخول إلى الخدمة.
- احتفظ بنسخة احتياطية دورية من **الإعدادات ← تنزيل نسخة احتياطية**؛ وهي مفيدة خصوصاً قبل إعادة نشر أو نقل الخدمة.
- لاستعادة بيانات من ملف، افتح البرنامج واختر **الإعدادات ← استعادة من ملف**.
- كلمة المرور مشتركة لكل من يستخدم الخدمة. غيّرها من إعدادات Render عند الحاجة، ولا تشاركها إلا مع الأشخاص المخولين.

## تحديث الموقع

أي `git push` إلى الفرع `main` يعيد نشر الخدمة تلقائياً على Render. عند تغيير ملفات `public/` ارفع رقم `VERSION` في `public/sw.js` ليتحدث التخزين المؤقت عند المستخدمين.
